# Метрики на val и математическое обоснование порога

Все числа получены **официальным `evaluate.py`** организаторов (обёртка `reid/eval`) на
hold-out val-сплите, построенном из `train.csv` (`reid/data/splits.py::holdout_val`, seed=42):
**375 query, 1528 gallery, 81 open-set (21.6 %)**, 294 query учитываются в mAP/Rank после
исключения open-set, junk-пары удаляются до усечения до 10.

> **Деплой-конфигурация.** Финальный раннер — fusion `224-only`, **TTA OFF**, GPU-preproc,
> ONNX fp16 (CUDA EP), k-reciprocal `k1=8,k2=3,λ=0.5,pool=300`. Его val-числа: **mAP@10 = 0.6909**,
> порог отказа **0.6970806**. Это единственная шкала, которая относится к сдаче.

---

## 1. Протокол метрик

### 1.1 Ранжирование (`submission.csv`, 45 % итогового балла)

- **Junk-пара**: объект галереи, у которого одновременно тот же `vehicle_id` **И** тот же
  `camera_id`, что у query, — удаляется из ранжирования **до** усечения до 10.
- Объекты той же камеры с **другим** `vehicle_id` остаются валидными сложными негативами.
- Query без валидного позитива после фильтра — **open-set** → **исключается** из mAP/Rank
  (не считается AP = 0).
- `AP = Σ (P@k · rel_k) / min(n_pos, 10)`, `mAP@10 = mean(AP)` (macro по закрытым query).
- `Rank-1` / `Rank-5` — попадание верного позитива в первые k (после junk-фильтра).
- Справочно из `embeddings.npy`: `mAP_full` (без усечения), `mINP` (n_pos / ранг последнего
  верного) — в баллы не идут. Мера — косинус, L2-нормированные векторы.

### 1.2 Кандидаты/отказ (`candidates.csv`, 10 %)

Уровень query, micro; учитывается только **top-1** кандидат.

- `TP` — пара есть, top-1 верный. `FP` — ответили, top-1 неверный (в т.ч. любой ответ на open-set).
- `FN` — пара есть, отказались. `TN` — пары нет, отказались.
- `F1 = 2PR/(P+R)`, `TNR = TN / (TN + FP_open-set)` (только open-set). `PR-AUC` — справочно.

### 1.3 Производительность (`tools/bench_perf.py`, 20 %)

`latency_b1` — медиана полного `extract()` (50 прогрев + 300 замеров, CUDA sync): ≤40 мс = 1.0,
40–80 линейно, >80 = 0. `throughput` — лучший FPS при batch 1/8/16/32 (≥10 с каждый): ≥100 = 1.0.
Веса ≤ 2 ГБ иначе дисквалификация из перф-блока.

## 3. Математическое обоснование порога отказа

### 3.1 Что такое confidence

`confidence = cos( q_i , g_{top-1} )` — **косинусная близость top-1** галереи после
полного пайплайна (fusion + GPU-preproc + per-query k-reciprocal, TTA OFF), L2-нормированные
векторы. Косинус — кросс-запросно сравнимая, монотонная шкала (в отличие от внутреннего min-max
`score` k-reciprocal, который нормируется внутри пула запроса: там много ровно 1.0, и TNR = 0
при любом пороге). Сравнение режимов скора на val (одинаковая точка max балла, деплой-шкала):

| Скор | Порог | F1 | TNR | `0.7F1+0.3TNR` |
|---|---|---|---|---|
| **cosine** | 0.6970806 | 0.9702 | 1.0 | **0.9792** |
| z-score по галерее | — | ≈0.94 | ≈0.84 | хуже |
| margin top1−top2 | — | ≈0.72 | ≈0.75 | хуже |

margin проигрывает: у одного ТС в галерее много кадров, top-2 близок к top-1 → кросс-запросная
уверенность шумная. z-score хуже cosine.

### 3.2 Как выбирается порог

Порог τ выбирается **на val** максимизацией целевой функции организаторов

```
τ* = argmax_τ  [ 0.7 · F1(τ) + 0.3 · TNR(τ) ]
```

где `F1(τ)` и `TNR(τ)` считаются micro на уровне query по top-1 (отказ = нет строки при
`confidence < τ`). Отбор выполняется **только по val**; тест и закрытые ответы не используются.

**Единый источник порога.** Замороженная константа — в `reid/calibrate.py`:
`DEFAULT_THRESHOLD_FUSION_FINAL = 0.6970806121826172`. Раннер
`service/infer/run.py::resolve_threshold` разрешает порог по порядку: `--threshold` → env
`REID_FUSION_THRESHOLD` → **`reports/calibration_fusion.json`** (`chosen.threshold`) → дефолт.

### 3.3 Числа и почему порог устойчив

На val (81 open-set, 294 закрытых), **деплой-шкала**:

- при τ = **0.6970806**: TP=277, FP=1, FN=16, TN=81 → **F1=0.9702, TNR=1.0**, балл **0.9792**,
  PR-AUC=0.9922; принимается 278/375;
- точка — **глобальный максимум** кривой `0.7·F1+0.3·TNR` на этой шкале; TNR = 1.0 означает,
  что ни один open-set не принят;
- кривая ступенчатая (rank-based), шаг TNR = 1/81 ≈ **1.23 %**, поэтому воспроизводимость
  зависит от детерминированных эмбеддингов и re-rank, а не от знаков порога.

### 3.4 Шкала порога

Порог привязан к конкретной пайплайн-шкале cosine:

| Пайплайн | Порог | Проверка |
|---|---|---|
| **fusion 224-only, TTA OFF (деплой)** | **0.6970806** | max `0.7F1+0.3TNR` на 224-only шкале |

Пороги иных конфигураций (TTA-шкала, w=0.6, DINOv2-only, SigLIP2-only) к деплой-шкале не
применяются и в решении не используются.

### 3.5 Ограничение и переносимость

Open-set в val — всего **81 запрос**, поэтому абсолютный порог несёт статистическую погрешность
порядка одного кадра. **Деплойный порог 0.6970806 откалиброван на 224-only шкале** (ONNX fp16
CUDA EP, GPU-preproc, pool=300), т.е. ровно на той, что отдаёт раннер:

- на тесте — **126 отказов / 1110 = 11.35 %** (984 принято), `validate_format` = OK;
- шаг TNR между «принять 0» и «принять 1» open-set равен одному запросу (1/81 = 1.23 %),
  поэтому на тесте доля отказов может отличаться от val.

Оговорка про режим `candidates.csv`: `confidence` — косинус top-1 **после** полного пайплайна и
калиброван на смеси near-duplicate (same-camera/same-ID) и кросс-камерных ответов; см. `errors.md`.
