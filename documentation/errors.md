# Честный анализ ошибок на val

Разбор типов ошибок выполнен **CPU-only** на диагностическом прогоне с точным junk/open-set
протоколом организаторов. Числовые `confidence` ниже — косинус top-1 на **диагностической шкале
анализа** (fusion + per-query k-reciprocal); они иллюстрируют механизмы ошибок и не
сопоставляются напрямую с деплойными значениями. Типы ошибок и выводы от шкалы не зависят.

> **Деплойная конфигурация:** fusion **224-only, TTA OFF**, GPU-preproc, ONNX fp16,
> k-reciprocal pool=300 → **mAP@10 = 0.6909**, порог отказа **0.6970806** (F1 0.9702 / TNR 1.0 /
> балл 0.9792).

**Важно про семантику:** `candidates.csv` пишет **сырой** top-1 (до junk-фильтра), а ранжирование
оценивается после junk-фильтра. Поэтому у **270 из 281** принятых запросов сырой top-1 — это
**та же камера + тот же `vehicle_id`** (near-duplicate кадр); официальный candidate-scorer считает
такой ответ верным (тот же автомобиль, `gal_vid == query_vid`). Итоговый mAP/Rank формируется уже
**кросс-камерными** матчами.

## Сводка по ошибкам (294 закрытых + 81 open-set)

| Категория | Кол-во | Комментарий |
|---|---|---|
| Принято (диагностический порог анализа) | 281 | TP = 279, FP = 2 |
| Отказ | 94 | из них 14 FN (есть позитив) + 80 TN |
| Rank-1 miss (после junk-фильтра, pool=300) | 84 / 294 | первый кросс-камерный позитив не на 1-м месте |
| AP@10 < 0.5 | 80 / 294 | «длинный хвост» трудных запросов |
| Концентрация ошибок по камере query | — | cam 89 → 10, cam 90 → 7, cam 11 → 6, cam 92 → 5 |

Редкость вида **не** является основным драйвером: медиана числа кадров ТС в галерее = 5 и для
miss, и для hit. Ошибки объясняются **внешним видом** (модель/цвет/ливрея), **ракурсом/окклюзией**
и **шумной шкалой confidence**, а не дефицитом кадров.

> Ниже для каждого кейса: `conf` — косинус top-1 на **диагностической шкале анализа** (не
> сравнивать напрямую с деплойным порогом 0.6970806);
> `first_crosscam_pos_rank` — ранг первого **кросс-камерного** позитива по полному косинусу
> (pool=300 ranking). Все id/скоры/ранги взяты из артефактов, ничего не выдумано.

## Кейс 1. Open-set FP: другой автомобиль той же модели/цвета

- query `75d99cef4f384abc885c0dabc22d86d7`, `vehicle_id=1481`, cam 11, bbox `181,543,739,465`.
- Принят с `confidence=0.7041` (выше порога анализа), предсказан `797` (cam 35), позитива в галерее нет.
- **Визуально:** оба кадра — синие BMW X5 (front 3/4), схожая модель и цвет, разное освещение/фон.
- **Причина:** дескриптор сильно кодирует модель/цвет; open-set объект выглядит как «типичный X5».
- **Замечание:** 0.7041 — **максимальный** confidence среди open-set запросов на этой шкале; порог
  выше него дал бы TNR = 1.0, но потерял бы F1 → балл падает.
- **Что делать:** синтетические hard-negatives «та же модель/цвет, другой ID»; усиление
  metric-learning; отдельный OOD/energy-скор поверх cosine.

## Кейс 2. Hard negative той же камеры (отказ = FN)

- query `c9e08cadf0e243a2a05d5050de9ea137`, `vehicle_id=757`, cam 90, 3 позитива.
- `confidence=0.6707` (**ниже порога анализа**) → **отказ**; сырой top-1 = `f9524d63…` `(278, cam 90)` —
  **та же камера**, другой автомобиль.
- **Причина:** объект той же сцены/освещения/времени похож сильнее, чем кросс-камерный позитив;
  скор оказался на 0.02 ниже порога.
- **Что делать:** camera-aware negative mining при обучении; нормировка скора по камере;
  осторожный сдвиг порога (он уже на плато).

## Кейс 3. FN при **верном** top-1: «белое на белом»

- query `39010b4e8e534411bc5723cfdf2c3c78`, `vehicle_id=848`, cam 95, 3 позитива.
- `confidence=0.6403` (**< порога**) → **отказ** (FN), хотя сырой top-1 — **верный автомобиль**
  `848` (другая камера, cam 69) и он же `first_crosscam_pos_rank = 1`.
- **Визуально:** все кадры — белые Toyota Highlander в окружении белых машин/светлого фона.
- **Причина:** низкий межкадровый контраст (белое на белом) занижает cosine верной пары.
- **Что делать:** hard-positive mining, нормализация экспозиции, лёгкое снижение порога — но это
  уменьшит TNR; приоритетнее улучшать эмбеддинг.

## Кейс 4. FN: частичный ракурс / окклюзия

- query `41da8a7145514ee3a1ea5ba96d26b482`, `vehicle_id=127`, cam 79, 5 позитивов.
- `confidence=0.5467` → **отказ**; первый кросс-камерный позитив только на
  **`first_crosscam_pos_rank = 22`**; top-1 — другой ID.
- **Визуально:** тёмно-синий/чёрный седан, преимущественно задне-боковой частичный вид.
- **Причина:** редкий ракурс + частичная видимость; признак «смазан».
- **Что делать:** расширить покрытие ракурсов аугментациями (уже без hflip); occlusion-aware
  обучение; при наличии — отбор кадров лучшего качества.

## Кейс 5. Rank-1 miss: одинаковая ливрея (такси)

- query `f241413df3704619b73d41b93bff90b2`, `vehicle_id=1373`, cam 86, 5 позитивов.
- Принят (`confidence=0.9657`, сырой top-1 — near-duplicate той же камеры, TP), но лучший
  **кросс-камерный** кандидат — лишь на **10-м** месте (`first_crosscam_pos_rank = 10`);
  AP@10 близок к нулю.
- **Визуально:** все кадры — белые кроссоверы в **одинаковой бело-оранжевой такси-ливрее**
  (Москва). Разные машины выглядят почти идентично.
- **Причина:** ливрея доминирует над индивидуальными признаками (шильдики/номера затёрты).
- **Что делать:** обучающие негативы «та же ливрея, другой ID»; цвето-инвариантные/локальные
  признаки (диски, вмятины, наклейки); multi-part токены.

## Кейс 6. Rank-1 miss: одна модель и цвет (белые Lada Niva)

- query `8d040d3da78b4e75861c7c74306597fe`, `vehicle_id=1505`, cam 89, 3 позитива.
- Принят (`confidence=0.9172`, near-duplicate top-1, TP), лучший кросс-камерный кандидат — на
  **`first_crosscam_pos_rank = 2`** (другой ID).
- **Визуально:** белые Lada Niva (одна модель), в т.ч. тюнинг/обвес.
- **Причина:** одинаковая модель+цвет; индивидуальные отличия (обвес) малы на 224 px.
- **Что делать:** part-based/attention-признаки, более высокое разрешение кропа для мелких деталей.

## Кейс 7. Rank-1 miss: тёмные SUV сливаются

- query `3a1a33dca623475c8e018d2e00c52104`, `vehicle_id=601`, cam 43, 5 позитивов.
- `confidence=0.5283` → **отказ** (FN); первый кросс-камерный позитив — лишь на
  **`first_crosscam_pos_rank = 38`**; top-1 — чужой ID из другой камеры (`744`, cam 16).
- **Визуально:** чёрные рамные SUV (Sorento / Grand Cherokee / Mercedes) при разном освещении,
  низкий локальный контраст.
- **Причина:** тёмные силуэты без различимых деталей; кодировка «общей геометрии» SUV.
- **Что делать:** tone-mapping/CLAHE-подобная предобработка, аугментации по экспозиции,
  hard-negative mining внутри класса SUV.

## Кейс 8. Rank-1 miss: сильная окклюзия соседними машинами

- query `3aaa60bfcf594ab79c61084325b76c51`, `vehicle_id=530`, cam 90, 4 позитива.
- `confidence=0.4128` → **отказ**; первый кросс-камерный позитив на
  **`first_crosscam_pos_rank = 186`**; top-1 — другой ID **той же камеры** (`111`, cam 90).
- **Визуально:** компактный тёмный кроссовер (Toyota C-HR) в плотном потоке; bbox захватывает
  соседние ТС.
- **Причина:** кроп «загрязнён» окружением, самого объекта мало.
- **Что делать:** маскирование/attention на центр bbox, обучение на окклюзиях, качество-гейт.

## Кейс 9. Катастрофический miss: редкий ракурс + тень

- query `065e9ef1b9bb483795b5cba866976bd9`, `vehicle_id=51`, cam 65, 3 позитива.
- Принят (`confidence=0.9232`, near-duplicate top-1 той же камеры, TP), но лучший
  **кросс-камерный** позитив — только на **`first_crosscam_pos_rank = 483`** по косинусу;
  в top-10 его нет.
- **Визуально:** тёмно-синий седан, задне-боковой вид в глубокой тени; bbox 581×357 (AR 1.63).
- **Причина:** сочетание редкого ракурса, тени и маленького масштаба объекта.
- **Что делать:** таргетные аугментации ракурса/освещения, cross-camera contrastive-сигнал,
  возможно ансамбль с SigLIP2 на трудных подмножествах (уже используется).

## Кейс 10. Системное: near-duplicate доминирует в top-1

- Пример: query `85dedafd16104144b59686751d850b52` (vid 47, cam 71), `confidence=0.8621`,
  принят; сырой top-1 = `79a946ef27d14104bf6f39e73d208838` (vid 47, **cam 71**, тот же кадр-дубликат).
- Всего **270/281** принятых ответов имеют сырой top-1 «та же камера + тот же ID».
- **Смысл:** ранжирование/порог «видит» в основном тривиальный near-duplicate, а ценный
  кросс-камерный сигнал проявляется только после junk-фильтра (в зачёт ранжирования).
- **Риск:** для query, у которого в галерее **нет** same-camera кадра (типично для open-set),
  top-1 сразу кросс-камерный и его cosine систематически ниже — отсюда и overlap распределений
  (см. `metrics.md §3`).
- **Что делать:** если разрешено — ограничивать `candidates` кросс-камерным кандидатом; явно
  документировать, что confidence калиброван на смеси near-duplicate и кросс-камерных ответов;
  в проде — отдельные пороги/нормировки для двух режимов.

## Как воспроизвести

Кейсы извлечены скриптом (CPU-only, read-only). Реализован junk-фильтр «тот же `vehicle_id`
И `camera_id`» **до** усечения top-10, AP@10 по `submission.csv`, полный кросс-камерный
cosine-ранг по `embeddings.npy`, затем сгруппированы FP/FN/Rank-1-miss/low-AP. Анализ
повторяется на любом val-прогоне.

## Выводы

1. Основной запас — **различение похожих объектов** (модель/цвет/ливрея) и **неразборчивые
   ракурсы/окклюзии**, а не нехватка кадров.
2. Деплойный порог **0.6970806** (224-only, TTA OFF) — сознательный компромисс F1/TNR
   (F1 0.9702 / TNR 1.0 / балл 0.9792): система скорее «осторожна» на закрытых и не пропускает
   open-set вовсе (TNR 1.0). Ранжирование при этом — **0.6909**.
3. Систематический near-duplicate в top-1 (270/281) — важный нюанс семантики `candidates.csv`,
   который следует держать в голове при интерпретации confidence.
